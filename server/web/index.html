A storage engine,
built from scratch.

A log-structured merge-tree key-value store in Go, using only the standard library: write-ahead log, skip-list memtable, SSTables with bloom filters, a MANIFEST, and size-tiered compaction. Every write is checksummed and fsynced before it is acknowledged, and survives a hard crash.

    How a write flows

    What happened when you pressed Put.

    1. 1

      Sequence number

      The write gets a unique, increasing 56-bit sequence number. Keys are stored as (key, seq, kind) and sorted newest-first, so a lookup stops at the first match.

    2. 2

      Write-ahead log

      The record is framed with a CRC-32C checksum and appended to the log. With group commit, one fsync covers every writer waiting at that moment.

    3. 3

      Memtable

      The entry goes into a skip list (p = 1/4, height 12) behind a read-write lock. Deletes become tombstones that shadow older versions.

    4. 4

      Flush

      A full memtable is frozen and written in the background to an SSTable: 4 KiB data blocks, a sparse index and a bloom filter, committed in the MANIFEST.

    5. 5

      Compaction

      Similar-sized tables are merged with a k-way min-heap merge, keeping the newest version of each key and dropping tombstones only when nothing older exists.

    Engineering highlights

    • Crash-tested

      A test kills the process at random moments mid-write, restarts it, and checks that no acknowledged write was lost, for every fsync policy.

    • Group commit

      Concurrent writers share one fsync. In tests, 200 sync requests needed only 38 fsyncs.

    • fsyncgate-safe

      A failed fsync makes the log refuse further writes, instead of retrying into silent data loss.

    • Torn-write recovery

      Tested at every possible crash byte offset: complete records are kept, the torn tail is trimmed.

    • Bloom filters

      Sized by m = -n ln p / (ln 2)². Lookups for absent keys skip about 99% of table reads.

    • Crash-safe compaction

      Every flush and merge commits through a fsynced MANIFEST edit; the crash test kills the process mid-flush and mid-compaction too.

    • Race-free

      Every test runs under Go's race detector in CI, on every push.

    • Hardened server

      Constant-time token checks, size limits, timeouts, rate-limited sandbox, and logs that never contain keys.
