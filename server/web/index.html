How a write flows

  1. Sequence number. Each write gets a unique, increasing 56-bit sequence number. Keys are stored as (user key, seq, kind), sorted newest-first, so a lookup stops at the first match.
  2. Write-ahead log. The record is framed with a CRC-32C checksum and appended to the log. With group commit, one fsync is shared by every writer waiting at the same time.
  3. Memtable. The write is inserted into a skip list (p = 1/4, max height 12) guarded by a read-write lock. Deletes are tombstones, not removals.
  4. Publish. Readers only see the write after it is durable, so a crash can never undo a value someone already read.
  5. Recovery. On restart the log is replayed. A torn final record is truncated; corruption in the middle stops startup instead of silently losing data.

Verified by a crash test that kills the process at random moments mid-write and checks that no acknowledged write was lost. SSTables, bloom filters and compaction are next on the roadmap.
